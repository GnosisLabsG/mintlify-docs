## Rate Limit Headers

When you make API requests, the response includes headers showing your current usage:

```http
X-RateLimit-Remaining: 45
X-RateLimit-Reset: 1640995200
Retry-After: 30
```

| Header | Description |
|--------|-------------|
| **X-RateLimit-Remaining** | Requests remaining in current window |
| **X-RateLimit-Reset** | Unix timestamp when limit resets |
| **Retry-After** | Seconds to wait before retrying (when rate limited) |

## HTTP Status Codes

### Success Responses

- **200 OK** - Request successful
- **201 Created** - Resource created successfully
- **207 Multi-Status** - Bulk operation with mixed results

### Rate Limiting Responses

- **429 Too Many Requests** - Rate limit exceeded

Example rate limit response:

```json
{
  "success": false,
  "error": "Rate limit exceeded. Please slow down your requests.",
  "code": 429,
  "retry_after": 60,
  "rate_limit_remaining": 0
}
```

## Handling Rate Limits

### Exponential Backoff

Implement exponential backoff when you receive 429 responses:

<CodeGroup>
```javascript JavaScript
async function apiRequestWithBackoff(url, options, maxRetries = 3) {
  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      const response = await fetch(url, options);
      
      if (response.status === 429) {
        const retryAfter = response.headers.get('Retry-After');
        const waitTime = retryAfter ? parseInt(retryAfter) * 1000 : Math.pow(2, attempt) * 1000;
        
        if (attempt === maxRetries) {
          throw new Error('Rate limit exceeded after maximum retries');
        }
        
        console.log(`Rate limited. Waiting ${waitTime}ms before retry ${attempt}/${maxRetries}`);
        await new Promise(resolve => setTimeout(resolve, waitTime));
        continue;
      }
      
      return response;
    } catch (error) {
      if (attempt === maxRetries) throw error;
      await new Promise(resolve => setTimeout(resolve, Math.pow(2, attempt) * 1000));
    }
  }
}
```

```python Python
import time
import requests
from requests.exceptions import RequestException

def api_request_with_backoff(url, headers, data=None, max_retries=3):
    for attempt in range(1, max_retries + 1):
        try:
            response = requests.post(url, headers=headers, json=data)
            
            if response.status_code == 429:
                retry_after = response.headers.get('Retry-After')
                wait_time = int(retry_after) if retry_after else 2 ** attempt
                
                if attempt == max_retries:
                    raise Exception('Rate limit exceeded after maximum retries')
                
                print(f'Rate limited. Waiting {wait_time}s before retry {attempt}/{max_retries}')
                time.sleep(wait_time)
                continue
            
            return response
            
        except RequestException as e:
            if attempt == max_retries:
                raise e
            time.sleep(2 ** attempt)
```
</CodeGroup>

### Rate Limit Monitoring

Monitor your usage to avoid hitting limits:

```javascript
class RateLimitMonitor {
  constructor() {
    this.remaining = null;
    this.resetTime = null;
  }

  updateFromHeaders(headers) {
    this.remaining = parseInt(headers.get('X-RateLimit-Remaining') || '0');
    this.resetTime = parseInt(headers.get('X-RateLimit-Reset') || '0');
  }

  shouldWait() {
    if (this.remaining === null) return false;
    
    // If we have less than 10% of requests remaining, slow down
    return this.remaining < 10;
  }

  timeUntilReset() {
    if (!this.resetTime) return 0;
    return Math.max(0, this.resetTime - Math.floor(Date.now() / 1000));
  }
}

// Usage
const monitor = new RateLimitMonitor();

async function makeRequest(url, options) {
  if (monitor.shouldWait()) {
    const waitTime = Math.min(monitor.timeUntilReset(), 60) * 1000;
    console.log(`Approaching rate limit. Waiting ${waitTime}ms`);
    await new Promise(resolve => setTimeout(resolve, waitTime));
  }

  const response = await fetch(url, options);
  monitor.updateFromHeaders(response.headers);
  
  return response;
}
```

## Best Practices

### Optimize Request Patterns

<AccordionGroup>
  <Accordion title="Batch Operations">
    Use bulk endpoints when possible to reduce request count:
    
    ```javascript
    // ❌ Multiple individual requests
    for (const file of files) {
      await uploadSingleFile(userId, file);
    }
    
    // ✅ Single bulk request  
    await uploadMultipleFiles(userId, files);
    ```
  </Accordion>

  <Accordion title="Efficient Polling">
    When checking status, use appropriate intervals:
    
    ```javascript
    // ❌ Aggressive polling
    setInterval(() => checkStatus(userId), 1000); // Every second
    
    // ✅ Smart polling with backoff
    let pollInterval = 5000; // Start with 5 seconds
    const maxInterval = 60000; // Max 60 seconds
    
    async function pollStatus() {
      const status = await checkStatus(userId);
      
      if (status.processing) {
        pollInterval = Math.min(pollInterval * 1.5, maxInterval);
        setTimeout(pollStatus, pollInterval);
      } else {
        console.log('Processing complete');
      }
    }
    ```
  </Accordion>

  <Accordion title="Request Queuing">
    Implement client-side queuing to control request rate:
    
    ```javascript
    class RequestQueue {
      constructor(rateLimit = 50) { // 50 requests per minute
        this.queue = [];
        this.processing = false;
        this.interval = 60000 / rateLimit; // ms between requests
      }
      
      async add(requestFn) {
        return new Promise((resolve, reject) => {
          this.queue.push({ requestFn, resolve, reject });
          this.process();
        });
      }
      
      async process() {
        if (this.processing || this.queue.length === 0) return;
        
        this.processing = true;
        
        while (this.queue.length > 0) {
          const { requestFn, resolve, reject } = this.queue.shift();
          
          try {
            const result = await requestFn();
            resolve(result);
          } catch (error) {
            reject(error);
          }
          
          // Wait before next request
          if (this.queue.length > 0) {
            await new Promise(resolve => setTimeout(resolve, this.interval));
          }
        }
        
        this.processing = false;
      }
    }
    ```
  </Accordion>
</AccordionGroup>

### Error Handling

Always handle rate limit errors gracefully:

```javascript
async function robustApiCall(apiFunction, ...args) {
  const maxRetries = 3;
  let attempt = 1;
  
  while (attempt <= maxRetries) {
    try {
      return await apiFunction(...args);
    } catch (error) {
      if (error.status === 429 && attempt < maxRetries) {
        const retryAfter = error.headers?.get('Retry-After') || Math.pow(2, attempt);
        console.log(`Rate limited. Retrying in ${retryAfter} seconds...`);
        await new Promise(resolve => setTimeout(resolve, retryAfter * 1000));
        attempt++;
      } else {
        throw error;
      }
    }
  }
}
```

## Common Scenarios

### High-Volume Document Processing

For applications processing many documents:

```javascript
// Efficient bulk processing
async function processLargeDocumentSet(userId, files) {
  const batchSize = 20; // Max files per request
  const batches = [];
  
  // Split into batches
  for (let i = 0; i < files.length; i += batchSize) {
    batches.push(files.slice(i, i + batchSize));
  }
  
  // Process batches with rate limiting
  const results = [];
  for (const batch of batches) {
    try {
      const result = await uploadMultipleFiles(userId, batch);
      results.push(result);
      
      // Wait between batches to respect rate limits
      if (batches.indexOf(batch) < batches.length - 1) {
        await new Promise(resolve => setTimeout(resolve, 6000)); // 10 requests/minute = 6s between
      }
    } catch (error) {
      if (error.status === 429) {
        // Handle rate limit with longer wait
        await new Promise(resolve => setTimeout(resolve, 60000));
        // Retry this batch
        const result = await uploadMultipleFiles(userId, batch);
        results.push(result);
      } else {
        throw error;
      }
    }
  }
  
  return results;
}
```

### Real-time Status Updates

For applications needing frequent status checks:

```javascript
// Smart status polling
class StatusPoller {
  constructor(userId, checkFunction) {
    this.userId = userId;
    this.checkFunction = checkFunction;
    this.pollInterval = 5000; // Start with 5 seconds
    this.maxInterval = 60000; // Max 1 minute
    this.backoffMultiplier = 1.2;
  }
  
  async startPolling() {
    while (true) {
      try {
        const status = await this.checkFunction(this.userId);
        
        if (status.completed) {
          return status;
        }
        
        // Increase interval for long-running processes
        if (status.estimated_time_remaining > 60) {
          this.pollInterval = Math.min(
            this.pollInterval * this.backoffMultiplier,
            this.maxInterval
          );
        }
        
        await new Promise(resolve => setTimeout(resolve, this.pollInterval));
        
      } catch (error) {
        if (error.status === 429) {
          // Rate limited - wait longer
          this.pollInterval = Math.min(this.pollInterval * 2, this.maxInterval);
          await new Promise(resolve => setTimeout(resolve, this.pollInterval));
        } else {
          throw error;
        }
      }
    }
  }
}
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Consistently hitting rate limits">
    **Solutions:**
    - Implement request queuing
    - Use bulk operations instead of individual requests
    - Increase delays between requests
    - Consider upgrading to higher limits
  </Accordion>

  <Accordion title="File upload failures">
    **Check:**
    - File size is under 10MB
    - Total request size is under 50MB
    - Not exceeding 20 files per bulk request
    - Upload rate is within 60/minute for single uploads
  </Accordion>

  <Accordion title="Inconsistent rate limit behavior">
    **Possible causes:**
    - Multiple API keys from same application
    - Requests from different IP addresses
    - Cached responses not counted against limits
    
    **Solutions:**
    - Use single API key per application
    - Implement centralized rate limiting
    - Monitor all request sources
  </Accordion>
</AccordionGroup>
