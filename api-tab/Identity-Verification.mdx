## What is Identity Verification?

Identity Verification is a security feature that allows your AI agent to securely identify and personalize interactions with users. When implemented, your agent can:

### Step 2: Implement Server-Side Hash Generation

You must generate user hashes on your server using HMAC-SHA256:

<CodeGroup>
```javascript Node.js
const crypto = require('crypto');

function generateUserHash(userId, secretKey) {
    return crypto
        .createHmac('sha256', secretKey)
        .update(userId)
        .digest('hex');
}

// Usage
const userId = 'user_12345';
const secretKey = 'your-secret-key-from-dashboard';
const userHash = generateUserHash(userId, secretKey);
```

```php PHP
function generateUserHash($userId, $secretKey) {
    return hash_hmac('sha256', $userId, $secretKey);
}

// Usage
$userId = 'user_12345';
$secretKey = 'your-secret-key-from-dashboard';
$userHash = generateUserHash($userId, $secretKey);
```

```python Python
import hmac
import hashlib

def generate_user_hash(user_id, secret_key):
    return hmac.new(
        secret_key.encode(),
        user_id.encode(),
        hashlib.sha256
    ).hexdigest()

# Usage
user_id = 'user_12345'
secret_key = 'your-secret-key-from-dashboard'
user_hash = generate_user_hash(user_id, secret_key)
```
</CodeGroup>

## How It Works

<Steps>
  <Step title="Server-Side Hash Generation">
    Generate a cryptographic hash using the user's ID and your secret key:
    ```
    HMAC-SHA256(user_id, secret_key) = user_hash
    ```
  </Step>
  
  <Step title="Client-Side Verification">
    Send three pieces of information to Mind-e:
    - **User ID**: The user's unique identifier
    - **User Hash**: The secure hash generated on your server
    - **User Metadata**: Additional user information (optional)
  </Step>
  
  <Step title="Mind-e Validation">
    Mind-e verifies the hash matches the user ID using your secret key. If valid, the AI gets access to the user's information.
  </Step>
</Steps>

### ❌ Security Anti-Patterns

<Accordion title="Common Security Mistakes">
  <AccordionItem title="Never Expose Secret Key Client-Side">
    ```javascript
    // ❌ Wrong - Secret key exposed
    const secretKey = 'your_secret_key'; // Never do this!
    const hash = crypto.createHmac('sha256', secretKey).update(userId).digest('hex');
    ```
    **Why it's wrong**: Anyone can view source and see your secret key.
  </AccordionItem>
  
  <AccordionItem title="Don't Generate Hashes in Browser">
    ```javascript
    // ❌ Wrong - Client-side hash generation
    function generateHashInBrowser(userId, secretKey) {
        // This is insecure - anyone can see the secret key
    }
    ```
    **Why it's wrong**: Client-side code is visible to all users.
  </AccordionItem>
  
  <AccordionItem title="Don't Include Sensitive Data">
    ```javascript
    // ❌ Wrong - Sensitive data in metadata
    {
        name: "John Doe",
        password: "secret123", // Never include passwords
        api_key: "sk_123456",  // Never include API keys
        ssn: "123-45-6789"     // Never include sensitive personal data
    }
    ```
    **Why it's wrong**: Metadata is sent to third-party service.
  </AccordionItem>
</Accordion>

## Troubleshooting

<Accordion title="Common Issues & Solutions">
  <AccordionItem title="Hash Verification Fails">
    **Symptoms**: AI doesn't recognize user information
    
    **Common Causes**:
    - Secret key mismatch
    - Incorrect hash algorithm
    - User ID mismatch between client and server
    
    **Solutions**:
    - Verify secret key is copied exactly from Mind-e dashboard
    - Ensure using HMAC-SHA256 algorithm
    - Check user ID is identical in all requests
  </AccordionItem>
  
  <AccordionItem title="Widget Not Loading Identity">
    **Symptoms**: `mindeChat('identify')` not working
    
    **Solutions**:
    - Ensure widget is fully loaded before calling identify
    - Check browser console for JavaScript errors
    - Verify all required parameters are provided
    - Test with direct method first
  </AccordionItem>
  
  <AccordionItem title="Metadata Issues">
    **Problem**: Metadata too large (>1000 characters)
    
    **Solution**: Reduce metadata size by:
    - Removing unnecessary fields
    - Using shorter field names
    - Storing large data server-side and referencing by ID
    
    **Problem**: Invalid JSON in metadata
    
    **Solution**: Validate JSON before sending:
    ```javascript
    try {
        JSON.stringify(userMetadata);
    } catch (error) {
        console.error('Invalid metadata JSON:', error);
    }
    ```
  </AccordionItem>
</Accordion>

## Best Practices

### 🔒 Security

<CardGroup cols={2}>
  <Card title="Authentication First" icon="shield-check">
    Always validate authentication before generating hashes
  </Card>
  <Card title="Environment Variables" icon="gear">
    Use environment variables for secret keys
  </Card>
  <Card title="Rate Limiting" icon="clock">
    Implement rate limiting on hash generation endpoints
  </Card>
  <Card title="Security Monitoring" icon="eye">
    Log verification attempts for security monitoring
  </Card>
</CardGroup>

### ⚡ Performance

- **Cache user hashes** when possible (with appropriate TTL)
- **Minimize metadata size** to reduce request overhead
- **Implement proper error handling** for network failures
- **Use async/await** for better error handling

### 👤 User Experience

- **Graceful degradation** - chat works without identity verification
- **Clear error messages** for developers (in console)
- **Fast identity setup** - don't block chat interface
- **Consistent user data** across sessions
